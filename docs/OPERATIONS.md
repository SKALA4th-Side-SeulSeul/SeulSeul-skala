# 운영자 명령 빠른 안내

운영 서버 `~/app`에서 실행합니다. **명령은 `./admin.sh` 하나만 기억하면 됩니다.** 터미널에서 실행하면 htop처럼 화면 전체를 쓰는 관리 콘솔이 열리고, 상태 확인부터 공지 처리·백업·재배포까지 메뉴에서 고를 수 있습니다.

루트에는 `admin.sh`·`view.sh`·`run.sh`·`stop.sh` 4개만 있습니다. 공지·재처리·안내 DM·백업 스크립트는 `scripts/`에 있고 `./admin.sh <하위 명령>`으로 실행합니다(D-041).

## 관리 콘솔 (`./admin.sh`)

```text
 슬슬 관리 콘솔 │ 10/07(수) 14:32:05             서비스 10초 · 공지 60초마다 새로고침   ← 상단 바
 서비스  ● 봇 실행 중   ● OAuth 실행 중   ● 터널 실행 중   ● DB 실행 중
 백업    ✔ 자동 백업 켜짐 (매일 03:00)   ✔ 마지막 성공 10/07 03:00 (보관 3개)
 ─────────────────────────────────────────────────────────────────────
 ■ 한눈에 보기 / 공지 상태 분포(막대 차트) / 다가오는 마감 7일 / 처리가 필요한 공지 / 최근 공지
 ─────────────────────────────────────────────────────────────────────
 ■ 메뉴  ↑↓←→ 고르기 · Enter 실행 · 번호를 누르면 바로 실행
   1  실패한 공지 AI로 다시 분석            6  가입 학생 전체에 안내 DM
   2  공지 직접 등록·수정·삭제              7  지금 DB 백업하기
   3  반영 안 된 Slack 원본 보기            8  자동 백업 켜기·끄기
   4  봇 로그 실시간 보기                   9  서비스 시작·재배포
   5  공지 대시보드 전체 보기               0  서비스 중지
 ┆ [공지] 고른 메뉴가 무엇을 하는지 설명이 여기에 나옵니다.
 ? 도움말   Enter 실행   1~0 바로 실행   r 새로고침   q 종료               ← 하단 바
```

| 키 | 동작 |
| --- | --- |
| `↑` `↓` `←` `→` | 메뉴 고르기. 고른 메뉴의 설명이 아래에 나옵니다. |
| `Enter` | 고른 메뉴 실행 |
| `1`~`9`, `0` | 해당 메뉴 바로 실행 |
| `?` | 화면 읽는 법과 공지 상태 용어 설명 |
| `r` | 지금 새로고침 (평소에는 서비스·백업 10초, 공지 60초마다 자동) |
| `q` | 콘솔 종료 |

- 메뉴를 실행하면 일반 화면으로 바뀌어 작업이 진행되고, 끝나면 `Enter`로 콘솔에 돌아옵니다. 작업 중 `Ctrl+C`는 그 작업만 멈춥니다.
- 백업·재처리·재배포·중지·자동 백업 끄기는 실행 전에 `y` 확인을 받습니다. 재배포(9)는 먼저 백업할지도 묻습니다.
- 창이 80×24보다 작거나 파이프로 실행하면 같은 메뉴를 줄 단위로 보여 줍니다. 일부러 줄 단위 메뉴를 쓰려면 `./admin.sh --simple`.

## 공지 상태 읽는 법

| 표시 | 뜻 | 할 일 |
| --- | --- | --- |
| `✔ 정상` | AI 분석이 끝나 체크리스트에 반영됨 | 없음 |
| `↻ 자동 재시도 대기` | 일시 장애로 실패, 봇이 5분·15분·1시간 간격으로 다시 시도 | 기다립니다 |
| `✖ 수동 조치 필요` | 자동 재시도도 실패 | 메뉴 1(AI 재분석) 또는 메뉴 2(직접 수정) |
| `⚠ 미적용 원본` | 받았지만 아직 반영 전 | 잠시 뒤에도 남으면 메뉴 3으로 확인, 필요하면 Slack 원문 수정·재게시 또는 메뉴 2 |

공지 패널의 "처리가 필요한 공지" 번호는 메뉴 1과 `./admin.sh retry N`의 번호와 같습니다. AI 재분석(메뉴 1)은 AI를 다시 호출하는 기능이고, 제목·요약·마감일을 직접 입력하려면 메뉴 2의 `수정`을 씁니다.

## 바로 실행하는 명령

메뉴와 같은 기능을 한 줄로 실행할 때 씁니다. 모든 명령은 `--help`로 설명을 볼 수 있습니다.

| 명령 | 용도 |
| --- | --- |
| `./admin.sh retry` | AI 분석 실패 공지 목록 (번호 확인) |
| `./admin.sh retry N` | N번 공지를 AI로 다시 분석 |
| `./admin.sh retry pending` | 반영되지 않은 Slack 원본 보기 |
| `./admin.sh notice` | 공지 등록·수정·삭제 (`--limit 100`, `--workspace-id T...`). 봇이 없는 채널도 등록 |
| `./admin.sh announce` | 가입 학생 전체에게 안내 DM (미리보기 후 `y`로 발송, 재실행 시 중복 발송) |
| `./admin.sh backup` | 지금 운영 DB 백업 |
| `./admin.sh backup status` | 자동 백업 예약과 최근 백업 확인 |
| `./admin.sh backup schedule` / `unschedule` | 매일 03:00 자동 백업 켜기 / 끄기 |
| `./view.sh` | 서비스 상태 |
| `./view.sh dashboard [--watch]` | 공지 대시보드 (`--watch`는 5초마다 갱신) |
| `./view.sh logs bot [--follow] [--tail 300] [--raw]` | 봇 로그 |
| `./view.sh logs manual [--follow] [--raw]` | 수동 공지 처리 성공·실패 기록 |
| `./view.sh db` / `schema` / `config` | 읽기 전용 psql / 테이블 목록 / 설정 검증 |
| `./run.sh` | 빌드·DB 준비·마이그레이션·재시작 (`postgres`, `migrate`, `setup`) |
| `./stop.sh` | 서비스 중지 (`bot`, `oauth`, `ngrok`, `postgres`). 데이터는 보존 |

## 봇이 없는 채널의 공지 등록 (D-042)

메뉴 2 → `1 등록`에서 Slack 원문 링크를 붙여 넣습니다. 워크스페이스는 자동으로 확인하므로 입력하지 않습니다.

- 원문 채널이 공지 채널 설정에 있으면 그 채널의 대상으로 바로 등록합니다.
- 설정에 없으면(봇이 없는 채널) 설정된 채널 목록이 `1) 광주 전체 · C…`, `2) 2반 · C…`처럼 나옵니다. **학생 배정 기준 채널**을 번호로 고르면 그 채널의 대상 학생에게 보이고, 학생 화면의 원문 링크는 실제 메시지로 연결됩니다.
- 봇이 없는 채널의 원문은 Slack에서 수정·삭제해도 자동으로 따라가지 않습니다. 메뉴 2의 `2 수정`·`3 삭제`로 처리합니다.
- 원문은 붙여 넣은 그대로 받습니다. 다 붙여 넣은 뒤 새 줄에 `.done`을 입력합니다. Slack 복사로 링크 주소가 빠졌다면 `제출 링크>`에서 링크만 따로 붙여 넣습니다.
- 공지 원문은 메뉴 2를 연 뒤에 붙여 넣으세요. 콘솔 화면이나 다른 질문에 붙여 넣은 글은 명령·답으로 쓰지 않고 버립니다.
- 실패하면 작업·단계·원인·해결 방법이 나오고 `./view.sh logs manual`에 기록됩니다.

식별자로 직접 재처리해야 할 때만 `./admin.sh retry retry --workspace-id '<ID>' --url '<제출 링크>' [--channel-id '<ID>' --message-ts '<ts>']`를 씁니다.

## 이전 명령에서 바뀐 점 (D-041)

| 이전 | 지금 |
| --- | --- |
| `./notice.sh` | 메뉴 2 또는 `./admin.sh notice` |
| `./notice_edit.sh` | 메뉴 2 → `2 수정` (같은 화면이라 제거) |
| `./retry.sh list` / `retry --index N` / `pending` | 메뉴 1·3 또는 `./admin.sh retry` / `retry N` / `retry pending` |
| `./announce.sh` | 메뉴 6 또는 `./admin.sh announce` |
| `./backup.sh` | 메뉴 7 또는 `./admin.sh backup` |
| `./backup_run.sh` / `./backup_stop.sh` | 메뉴 8 또는 `./admin.sh backup schedule` / `unschedule` |

**자동 백업을 이미 등록했다면** 코드를 받은 뒤 한 번 `./admin.sh backup schedule`(또는 메뉴 8 → `s`)을 실행하세요. 이전 예약은 옮겨진 루트 `backup.sh`를 실행하므로 다시 등록하기 전까지 예약 백업이 실패합니다. 재등록 전에는 운영 명령을 실행할 때마다 경고가 나옵니다.

`.env` 변경 후에는 `./run.sh`(메뉴 9)로 컨테이너를 재생성해야 반영됩니다. 운영 DB를 직접 수정하거나 Docker Compose로 두 번째 봇을 실행하지 않습니다.
