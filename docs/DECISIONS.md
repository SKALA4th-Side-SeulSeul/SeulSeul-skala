## D-035 — 운영 PostgreSQL 호스트 포트 15432 통일

- 날짜: 2026-09-22
- 상태: 저장소 Compose·접속 문서 반영. 운영 서버 재생성 및 SSH 터널 확인은 별도.
- 내용: 운영 PostgreSQL은 서버의 `127.0.0.1:15432`에만 바인딩하고 컨테이너 내부 포트는 `5432`로 유지합니다. 봇의 Compose 네트워크 주소 `postgres:5432`와 로컬 개발 DB 포트는 변경하지 않습니다. DBeaver와 SSH 터널의 운영 DB 목적지는 `127.0.0.1:15432`를 사용합니다.
- 이유: 운영 DB를 외부 인터페이스에 공개하지 않으면서 DBeaver 접속에 사용하는 호스트 포트를 저장소 설정과 문서에서 일치시키기 위함입니다.
- 결과: 서버에서 `./run.sh`를 실행해 PostgreSQL 컨테이너를 재생성해야 적용됩니다. `docker compose port postgres 5432`의 출력은 `127.0.0.1:15432`여야 하며, 기존 데이터 볼륨은 삭제하지 않습니다.

- 결과: `deadline_source_text`는 AI가 선택한 마감일의 근거를 설명하는 값으로 저장합니다. 원문 전체는 별도로 보존하며, 원문 후보와 날짜·시각이 일치하지 않는 AI 결과는 저장하지 않습니다.

Qwen3 요청에는 최상위 `think=false`, `stream=false`, `keep_alive=5m`과 공지 분석용 JSON Schema를 보내고, `temperature=0.2`, `top_p=0.8`, `num_ctx=2048`, `num_predict=256`은 `options` 안에 둡니다. - 결과: 환경변수만으로 thinking을 끄는 것이 아니라, Ollama 호출 경계에서 실제 `think=false`를 전송합니다. 운영 전환 시 컨테이너 네트워크에서 Ollama 주소가 접근 가능한지 별도로 확인해야 합니다.

## D-030 — DB 구조 변경 없는 일시 장애 자동 재처리

- 날짜: 2026-09-20. 사용자 요청 및 DB 구조 변경하지 않는 방식 선택.
- AI 연결 실패·timeout·HTTP 429/5xx, Slack 원문 링크의 일시 장애만 자동 대상입니다. 분석 결과 검증·인증·권한·설정·예상 밖 예외는 제외합니다. 순간 재시도 여부와 지연 자동 대상 여부를 분리합니다.
- 기존 `next_retry_at`은 자동 대상 예약, `retry_count`는 이번 버전에서 새로 기록하는 지연 자동 처리 횟수(0~3)입니다. 과거 값은 순간 재시도 횟수였으므로 예약 없는 기존 행은 자동으로 분류하거나 초기화하지 않습니다.
- 최초 실패 완료 후 5분, 다시 실패 후 15분, 다시 실패 후 1시간에 최대 3회 추가 처리합니다. 각 처리의 즉시 분석 시도는 기존 최대 3회를 유지합니다. 성공·비일시적 실패·3회 소진·삭제 시 예약을 없앱니다. 명시적 수동 AI 재분석·새 원문 수정은 새 예산으로 처리합니다. 수동 permalink 조회가 실패하면 분석 전에 중단하고 기존 횟수·예약·실패 기록을 유지합니다.
- 단일 운영 봇의 별도 작업에서 30초마다 최대 10건 확인합니다. 원본이 처리 중이거나 삭제됐다면 제외합니다. 원본 변경·예약·횟수 비교와 조건부 갱신으로 늦게 끝난 결과의 덮어쓰기를 방지합니다.
- 실행 전에 횟수와 다음 예약을 먼저 저장합니다. 강제 종료에도 동일 차례가 무한 반복되지 않으나, 호출 전 종료도 한 차례를 소비합니다. 최종 차례에서 종료되면 운영자가 확인해야 합니다. 전용 영속 작업 큐·lease 및 외부 호출 exactly-once는 제공하지 않습니다.
- 자동 복구 성공 시 기존 DM을 갱신하며 수정 실패의 마지막 성공 분석과 완료 기록은 보존합니다. `pending` 원본은 입력 본문이 없으므로 자동 복구 대상이 아닙니다. 모델·마이그레이션·manifest 변경 없음.

## 운영 DB 조회 정책 변경 — 2026-09-20

아래는 2026-09-20 당시의 최초 구성 결정입니다. 호스트 포트는 D-035에서 `15432`로 후속 변경했으며, 현재 접속 절차는 `docs/DB-ACCESS.md`를 따릅니다. 최초 전용 키 계정안이 실제 서버에 적용됐다고 가정하지 않습니다.

- 당시 사용자 승인으로 기존 `ports:` 전면 금지 정책의 예외를 허용하고 운영 PostgreSQL을 `127.0.0.1:5432:5432`로 바인딩했습니다. 호스트 포트는 D-035에서 `127.0.0.1:15432:5432`로 변경했습니다. 외부 인터페이스 공개와 DB 포트 방화벽 개방은 계속 금지합니다.
- DBeaver는 별도 키 인증 SSH 터널 계정으로 목적지 `127.0.0.1:5432`에만 접근하고 조회 전용 DB 계정을 사용합니다. 기존 `seulseul` 배포 계정의 포워딩 금지는 유지합니다.
- 서버 SSH 정책 확인·관리자 세션 보존·문법 및 Match 효과 검사 후 reload하며, 실제 서버 적용 및 연결 확인은 아직 미완료입니다. 상세 절차는 `docs/DB-ACCESS.md`를 따릅니다.

중요한 구조·정책·외부 연동 결정을 날짜, 상태, 내용, 이유로 짧게 기록합니다. 시도했다가 버린 방법은 "포기한 대안"에, 에이전트가 지켜야 할 행동은 "결과"에 적습니다. 결정을 바꾸면 기존 항목을 지우지 말고 후속 항목을 추가합니다.

## D-011 — AI 분석 결과와 실패 처리

- 날짜: 2026-09-14
- 상태: 확정
- 내용:
  - AI는 `title`, `summary`, `deadline_at`, `deadline_source_text`를 포함한 JSON 객체를 반환합니다.
  - `title`은 체크리스트 제목, `summary`는 학생이 해야 할 행동을 포함한 요약, `deadline_at`은 ISO 8601 형식의 마감 시각, `deadline_source_text`는 마감일 판단에 사용한 원문의 표현입니다.
  - 기준 시간대는 `Asia/Seoul`이며, 날짜만 있고 시각이 없으면 해당 날짜의 `23:59`로 처리합니다.
  - 공지에는 마감일이 정확히 하나 존재한다는 제품 전제를 둡니다. 모든 필드는 필수이며, JSON 형식 오류·빈 필드·해석할 수 없는 마감일·여러 마감일은 분석 실패로 처리합니다.
  - `deadline_source_text`가 실제 원문에 존재하는지 검증해 원문에 없는 마감일 생성을 막습니다.
  - 분석에 실패하면 오류 원인을 포함해 최초 호출을 포함한 최대 3회까지 시도합니다. 계속 실패한 신규 공지는 체크리스트를 생성하거나 DM을 보내지 않고 `processing_failed` 상태와 실패 원인을 기록합니다.
  - 기존 공지의 수정 내용을 분석하다 실패하면 기존 체크리스트를 유지하고 갱신하지 않습니다.
- 이유: AI의 자유 형식 응답과 잘못된 마감일이 학생의 체크리스트와 알림으로 바로 전달되는 것을 막기 위함입니다.

## D-012 — 공지 식별, 링크 중복과 원본 변경

## D-014 — 링크 하나를 공지 하나로 처리

- 날짜: 2026-09-14
- 상태: 확정
- 내용:
  - D-012의 Slack 원본 메시지 단위 처리 방식을 보완해, D-009의 조건을 만족하는 링크 하나를 공지 하나로 처리합니다.
  - 한 Slack 메시지에 처리 가능한 링크가 여러 개 있으면 링크마다 별도의 공지와 학생별 체크리스트를 생성합니다.
  - 원본 메시지는 `workspace_id + channel_id + message_ts`로 식별하고, 개별 공지는 이 값에 `canonical_url`을 더해 식별합니다.
  - 학생에게 제공할 `original_url`은 원문 그대로 저장합니다. 중복 판정용 `canonical_url`은 query string, fragment와 마지막 `/`를 제거해 만듭니다.
  - 단축 URL과 단축 URL이 가리키는 원본 URL은 자동으로 같은 링크라고 판정하지 않습니다.

- 이유: 한 메시지에 서로 다른 제출 링크가 함께 올라와도 각 할 일을 독립적으로 완료하고 알림 받을 수 있게 하기 위함입니다.
- 결과: D-012의 `canonical_url` 중복 정책은 개별 링크마다 적용합니다.

- 이유: 공지·학생·개인별 완료 상태의 관계는 분리하되, AI 실패만을 위한 테이블은 만들지 않아 초기 스키마를 단순하게 유지하기 위함입니다.

  - `slack-manifest.yaml`에 `/seulseul`, `users:read`, 공지 메시지 이벤트와 Socket Mode 설정을 기록합니다.

- 정규화 URL이 UTF-8 2,048바이트를 넘거나 원문에 NUL이 있으면 저장 불가능한 공지 행을 만들지 않고 원본의 `applied=false`를 유지합니다. 로그와 `pending`으로 확인하고 원문을 수정하며, 링크를 잘라 다른 링크로 취급하지 않습니다.
- `Retry-After`가 60초를 초과하거나 비유한 값이면 기다리지 않고 실패 기록을 남깁니다. 예기치 못한 분석기 예외도 정제한 실패 사유로 저장하고 기존 CLI로 재처리합니다.
- permalink 조회 실패는 AI 호출 없이 원문 링크가 빈 실패 공지로 저장합니다. 학생에게는 표시하지 않고 선택 재처리 때 Slack 원문 링크를 다시 조회한 뒤 분석합니다. 조회가 다시 실패하면 기존 실패 기록을 유지합니다. 실패 목록에는 원본 식별자를 제공하며 원문 전체를 출력하지 않습니다. D-019의 로그만 남기고 버리던 동작을 대체합니다.
- `pending` CLI는 미적용 원본(`applied=false`) 식별자만 읽기 전용 조회합니다. 정상 처리 중인 항목도 포함되며 원본 본문 재전달 없이 자동 복구하지 않습니다. 삭제 원본 등은 운영자 확인이 필요합니다.
- 예약 백업 호스트 작업에는 systemd 30분 실행·30초 종료 상한을 둡니다. 컨테이너 내부 `pg_dump` 종료나 강제 종료 시 파일 정리까지 보장하지 않으며 시간 초과는 실패로 점검합니다. Docker 부팅 순서나 외부 백업은 이번 변경 범위가 아닙니다.
