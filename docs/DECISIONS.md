# 결정 기록

중요한 구조·정책·외부 연동 결정을 날짜, 상태, 내용, 이유로 짧게 기록합니다. 시도했다가 버린 방법은 "포기한 대안"에, 에이전트가 지켜야 할 행동은 "결과"에 적습니다. 결정을 바꾸면 기존 항목을 지우지 말고 후속 항목을 추가합니다.

## D-001 — 도메인별 src 구조 유지

- 날짜: 2026-09-13
- 상태: 확정
- 내용: `src/seulseul` 아래에 Slack, 공지, AI, 사용자, 체크리스트, 작업 도메인을 분리합니다.

- 포기한 대안: 하위 패키지마다 `__init__.py` 추가. 테스트는 `pythonpath = ["src"]`로 동작해 설치형 배포 전까지 불필요하므로 제거했습니다.
- 결과: wheel·Docker 등 설치형 배포를 준비할 때 하위 패키지 `__init__.py`를 추가합니다.

## D-003 — main 브랜치만 사용, PR·리뷰 규칙 보류

- 날짜: 2026-09-14
- 상태: 확정
- 내용: 브랜치는 `main`만 사용합니다. push 전에 `git pull --rebase`로 동료의 변경을 받고 `./scripts/check.sh`를 통과시킵니다. PR·리뷰 규칙은 보류하고, 도입할 때 후속 항목으로 기록합니다.
- 이유: 구조 설계 단계의 2인 팀에서 브랜치 관리 비용을 없애기 위함입니다.
- 포기한 대안:
  - `main`(안정)·`dev`(통합) 2개 브랜치 운영: 2인 팀에 관리 비용이 커서 채택하지 않았습니다.
  - 기능 브랜치와 PR(첫 커밋의 `COLLABORATION.md`): 보류했습니다.
- 결과: 에이전트는 브랜치 생성이나 PR 도입을 제안하지 않습니다.

## D-004 — 기준 문서 한 곳 유지와 환경변수 접근 제한

- 날짜: 2026-09-14
- 상태: 확정
- 내용: 설치·검증은 `README.md`, 환경변수·코드 규칙과 작업 흐름은 `COLLABORATION.md`, 구조·경계는 `docs/ARCHITECTURE.md`, 브랜치·커밋·합의 절차는 이 문서를 기준으로 둡니다. 다른 문서는 내용을 반복하지 않고 기준 문서를 가리킵니다. `config.py` 밖의 환경변수 접근은 Ruff `TID251`로 차단합니다.
- 이유: 문서 간 불일치를 줄이고 환경변수 읽기 지점을 하나로 유지하기 위함입니다.
- 포기한 대안:
  - pre-push hook(`.githooks/pre-push`)으로 push 전 검증 자동 실행: 팀 합의 없이 도입하는 강제 장치라 제외했습니다.
  - `COLLABORATION.md`에 브랜치·구조 규칙까지 함께 적는 방식: 규칙 하나를 바꿀 때 여러 문서를 고쳐야 했고 실제로 문서끼리 반대 내용이 되어, 기준 문서를 가리키는 구조로 바꿨습니다.
- 결과: 에이전트는 hook, pre-commit, CI 같은 강제 장치를 사용자 요청 없이 추가하지 않습니다.

## D-005 — 커밋 메시지 형식

- 날짜: 2026-09-14
- 상태: 확정
- 내용: 커밋 메시지는 `<타입>: <한국어 설명>` 형식으로 쓰고, 한 커밋에는 하나의 목적만 담습니다.

| 타입 | 용도 | 예시 |
| --- | --- | --- |
| `feat` | 기능 추가·변경 | `feat: 체크리스트 배정 서비스 추가` |
| `fix` | 버그 수정 | `fix: 마감일 없는 공지의 알림 누락 수정` |
| `refactor` | 동작 변경 없는 구조 개선 | `refactor: 공지 채널 검증 로직 분리` |
| `test` | 테스트만 추가·수정 | `test: 중복 체크리스트 생성 테스트 추가` |
| `docs` | 문서만 수정 | `docs: 커밋 규칙 정리` |
| `chore` | 설정, 의존성, 스크립트 등 | `chore: Ruff 설정 추가` |

- 이유: 제목만으로 변경 종류를 구분하고, 설명은 팀이 쓰는 언어로 통일하기 위함입니다.
- 포기한 대안:
  - `Add checklist ...`처럼 영어 동사로 시작하는 형식(첫 커밋의 `COLLABORATION.md`): 실제 커밋 방식과 달라 바꿨습니다.
  - `add` 타입: `feat`, `test`, `docs`, `chore`와 경계가 겹쳐 두지 않습니다.

## D-008 — check.sh가 개발 환경을 자동 준비

- 날짜: 2026-09-14
- 상태: 확정
- 내용: `./scripts/check.sh`는 검증 전에 `.venv`를 Python 3.11로 준비합니다. `.venv`가 없거나 버전이 다르면 다시 만들고, pytest·ruff가 없거나 `pyproject.toml`이 바뀌었으면 `pip install -e '.[dev]'`를 다시 실행합니다. Python 3.11 자체는 설치하지 않고 안내만 합니다.
- 이유: 3.11이 아닌 Python으로 만든 `.venv`나 의존성 미설치 때문에 팀원 환경에서 2단계 테스트가 `No module named pytest`로 실패했기 때문입니다.
- 포기한 대안: 실패 시 안내 메시지만 출력. 원인을 사람이 해석하고 명령을 직접 실행해야 해서 채택하지 않았습니다.
- 결과: 에이전트는 모듈 누락 오류를 `.venv` 직접 수정이 아니라 `./scripts/check.sh` 재실행으로 해결합니다.
