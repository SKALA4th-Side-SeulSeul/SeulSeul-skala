## D-005 — 커밋 메시지 형식

- 날짜: 2026-09-14
- 상태: 확정
- 내용: 커밋 메시지는 `<타입>: <한국어 설명>` 형식으로 쓰고, 한 커밋에는 하나의 목적만 담습니다.

| 타입 | 용도 | 예시 |
| --- | --- | --- |
| `feat` | 기능 추가·변경 | `feat: 체크리스트 배정 서비스 추가` |
| `fix` | 버그 수정 | `fix: 마감일 없는 공지의 알림 누락 수정` |
| `refactor` | 동작 변경 없는 구조 개선 | `refactor: 공지 채널 검증 로직 분리` |
| `test` | 테스트만 추가·수정 | `test: 중복 체크리스트 생성 테스트 추가` |
| `docs` | 문서만 수정 | `docs: 커밋 규칙 정리` |
| `chore` | 설정, 의존성, 스크립트 등 | `chore: Ruff 설정 추가` |

- 이유: 제목만으로 변경 종류를 구분하고, 설명은 팀이 쓰는 언어로 통일하기 위함입니다.
- 포기한 대안:
  - `Add checklist ...`처럼 영어 동사로 시작하는 형식(첫 커밋의 `COLLABORATION.md`): 실제 커밋 방식과 달라 바꿨습니다.
  - `add` 타입: `feat`, `test`, `docs`, `chore`와 경계가 겹쳐 두지 않습니다.

## D-008 — check.sh가 개발 환경을 자동 준비

- 날짜: 2026-09-14
- 상태: 확정
- 내용: `./scripts/check.sh`는 검증 전에 `.venv`를 Python 3.11로 준비합니다. `.venv`가 없거나 버전이 다르면 다시 만들고, pytest·ruff가 없거나 `pyproject.toml`이 바뀌었으면 `pip install -e '.[dev]'`를 다시 실행합니다. Python 3.11 자체는 설치하지 않고 안내만 합니다.
- 이유: 3.11이 아닌 Python으로 만든 `.venv`나 의존성 미설치 때문에 팀원 환경에서 2단계 테스트가 `No module named pytest`로 실패했기 때문입니다.
- 포기한 대안: 실패 시 안내 메시지만 출력. 원인을 사람이 해석하고 명령을 직접 실행해야 해서 채택하지 않았습니다.
- 결과: 에이전트는 모듈 누락 오류를 `.venv` 직접 수정이 아니라 `./scripts/check.sh` 재실행으로 해결합니다.

## D-011 — AI 분석 결과와 실패 처리

- 날짜: 2026-09-14
- 상태: 확정
- 내용:
  - AI는 `title`, `summary`, `deadline_at`, `deadline_source_text`를 포함한 JSON 객체를 반환합니다.
  - `title`은 체크리스트 제목, `summary`는 학생이 해야 할 행동을 포함한 요약, `deadline_at`은 ISO 8601 형식의 마감 시각, `deadline_source_text`는 마감일 판단에 사용한 원문의 표현입니다.
  - 기준 시간대는 `Asia/Seoul`이며, 날짜만 있고 시각이 없으면 해당 날짜의 `23:59`로 처리합니다.
  - 공지에는 마감일이 정확히 하나 존재한다는 제품 전제를 둡니다. 모든 필드는 필수이며, JSON 형식 오류·빈 필드·해석할 수 없는 마감일·여러 마감일은 분석 실패로 처리합니다.
  - `deadline_source_text`가 실제 원문에 존재하는지 검증해 원문에 없는 마감일 생성을 막습니다.
  - 분석에 실패하면 오류 원인을 포함해 최초 호출을 포함한 최대 3회까지 시도합니다. 계속 실패한 신규 공지는 체크리스트를 생성하거나 DM을 보내지 않고 `processing_failed` 상태와 실패 원인을 기록합니다.
  - 기존 공지의 수정 내용을 분석하다 실패하면 기존 체크리스트를 유지하고 갱신하지 않습니다.
- 이유: AI의 자유 형식 응답과 잘못된 마감일이 학생의 체크리스트와 알림으로 바로 전달되는 것을 막기 위함입니다.

## D-012 — 공지 식별, 링크 중복과 원본 변경

- 날짜: 2026-09-14
- 상태: 확정
- 내용:
  - Slack 원본 메시지는 `workspace_id + channel_id + message_ts` 조합으로 식별합니다.
  - URL을 정규화한 `canonical_url`을 별도의 링크 중복 판별 키로 사용합니다. 불필요한 쿼리 문자열, fragment와 마지막 `/`의 차이는 제거합니다.
  - 서로 다른 Slack 메시지라도 `canonical_url`이 같으면 이미 처리한 링크로 보고 체크리스트를 추가 생성하지 않습니다.
  - 원본 메시지가 수정되면 D-009의 채널·URL 조건을 다시 검증합니다. AI 분석에 성공하면 기존 공지와 학생별 체크리스트의 제목·요약·마감일을 갱신하되 학생별 완료 상태는 유지합니다.
  - 수정된 원본이 더 이상 처리 조건을 만족하지 않거나 원본 메시지가 삭제되면 연결된 공지와 학생별 체크리스트를 삭제 상태로 전환하고 예정된 DM 알림도 취소합니다.
  - 원본 수정 내용의 AI 분석에 실패하면 기존 데이터를 유지합니다.
- 이유: Slack 이벤트의 중복 수신과 같은 링크의 반복 게시로 체크리스트가 중복 생성되는 것을 막고, 원본 공지의 변경을 학생별 체크리스트에 일관되게 반영하기 위함입니다.

## D-013 — AI 제공자 선택

- 날짜: 2026-09-14
- 상태: 확정 (개발 단계)
- 범위: AI 제공자와 모델 선택만 다룹니다. AI 응답 형식·검증·재시도·실패 처리는 D-011을 따릅니다.
- 내용: AI 호출은 OpenAI 호환 `/chat/completions` 클라이언트 하나로 하고, `AI_PROVIDER`로 `nvidia`(NVIDIA Build API) 또는 `ollama`(로컬 LLM)를 고릅니다. 비워 두면 AI를 쓰지 않습니다. 모델 이름은 `NVIDIA_MODEL`, `OLLAMA_MODEL`로 지정하고 코드에 고정하지 않습니다.
- 이유: API 키가 없는 개발자도 로컬 LLM으로 테스트할 수 있고, 두 제공자 모두 OpenAI 호환 API를 지원하기 때문입니다.
- 포기한 대안 (로컬 연결 테스트 1회 기준): `qwen3.5:2b`는 추론 과정만 출력해 요약이 비었고, `qwen2.5:0.5b`는 요약 형식을 지키지 못했습니다. 개발 기본 모델은 `llama3.2`를 씁니다.
- 결과: `nvidia`를 쓰면 공지 원문이 외부로 전송되므로, 실제 워크스페이스 운영 전에 데이터 정책을 정해야 합니다.

## D-014 — 링크 하나를 공지 하나로 처리

- 날짜: 2026-09-14

- 내용:

- 이유: 한 메시지에 서로 다른 제출 링크가 함께 올라와도 각 할 일을 독립적으로 완료하고 알림 받을 수 있게 하기 위함입니다.

## D-021 — 학생 가입·해지 명령과 성명 형식

  - 해지하면 학생 개인정보와 외래 키로 연결된 개인 체크리스트를 물리적으로 삭제하고 공유 공지는 유지합니다.
  - `slack-manifest.yaml`에 `/seulseul`, `users:read`, 공지 메시지 이벤트와 Socket Mode 설정을 기록합니다.
- 이유: 가입 의사를 먼저 받은 사용자만 프로필을 조회·저장하고, 사용자가 지정한 성명 필드로 광주캠퍼스 반을 일관되게 판별하기 위함입니다.
- 변경: 사용자의 요청에 따라 소속 판별 기준을 표시 이름에서 성명으로 변경했습니다.

## D-022 — 실패 공지의 운영자 선택 재처리

- 날짜: 2026-09-16

- 배경: AI 서버 연결을 복구해도 저장된 실패 공지는 링크 중복 검사로 다시 분석되지 않습니다.

- 이유: 기존 중복 방지 정책과 학생 권한은 유지하면서 운영자가 실패 기록을 직접 복구할 수 있게 하기 위함입니다.

  - 신규 분석·운영자 재처리 성공, 가입, 완료·취소, 마감 경과를 반영해 당일 메시지를 갱신합니다. 가입 시 마감 전 기존 공지도 배정하며 반이 바뀌면 현재 소속에 맞는 항목만 보여 줍니다. 이전 완료 기록은 초기화하지 않습니다.
  - `SLACK_NOTICE_TARGETS`에 허용 채널 각각의 대상을 `채널ID=all` 또는 `채널ID=1~4`로 명시합니다. 누락·불일치는 앱 시작 시 오류로 처리하며 전체 배정을 추정하지 않습니다.
  - `daily_checklist_messages`에 학생·날짜별 유일한 발송 기록과 DM 채널·메시지 ts, 표시 상태, 전송 lease·실패 상태를 둡니다. 해지 시 학생과 함께 삭제합니다. Slack에 이미 보낸 메시지는 삭제하지 않되 과거 버튼의 권한은 차단합니다.
  - 단일 봇 프로세스의 주기 작업이 30초 간격으로 DB를 확인하며 새 공지·가입·버튼 동작 때 즉시 깨웁니다. DB lease로 동시 발송을 막고, 내용이 같으면 Slack API를 호출하지 않습니다.
  - 첫 발송의 응답 유실·프로세스 중단처럼 성공 여부가 불명확하면 `uncertain`으로 기록하고 자동 재발송하지 않습니다. 운영자가 Slack과 DB를 확인해야 합니다. 명확한 일시적 실패와 메시지 수정 실패는 지연 후 재시도합니다.
  - `chat:write`, `im:write`를 추가합니다. 공지 원문 수정·삭제 이벤트 수집은 별도 미완료 작업으로 유지합니다.
- 합의 범위: 일일 메시지 모델·마이그레이션, 채널 대상 설정과 `.env.example`, Slack manifest 변경을 이번 요청의 구현 범위로 승인받았습니다. 새 스케줄러 의존성은 추가하지 않습니다.

## D-024 — 원본 수정·링크 변경·삭제 동기화

- 날짜: 2026-09-17
- 상태: 확정 (사용자가 구현과 원본 상태 테이블·마이그레이션 추가 승인)
- 내용:
  - 수정은 `message.ts`, 삭제는 `deleted_ts`를 원본 식별자로 사용합니다. 설정 채널·스레드 제외·자신의 봇 제외 정책은 유지합니다. 수정·삭제 이벤트에 `channel_type`이 없어도 설정된 채널에서 전달된 이벤트는 허용합니다.
  - `notice_sources`에 원본 식별자, 최신 이벤트 시각, 적용 여부와 원본 삭제 여부만 저장합니다. AI 호출 전 짧은 트랜잭션에서 버전을 예약하고, 결과 저장 시 최신 버전인 경우만 반영합니다. DB 트랜잭션을 AI 호출 동안 열어 두지 않습니다.
  - 유지한 링크의 제목·요약·마감일은 재분석에 성공했을 때 갱신하며 학생별 완료 상태는 유지합니다. 실패 시 최신 원문과 오류를 재처리용으로 저장하되 마지막 성공 분석과 기존 체크리스트를 유지합니다.
  - 제거된 링크는 공지와 체크리스트를 함께 soft delete합니다. 같은 원본에 다시 추가되면 성공한 분석에 한해 기존 체크리스트를 복구하고 완료 기록도 유지합니다. 다른 원본이 이미 소유한 중복 링크는 덮어쓰거나 이동하지 않습니다.
  - 원본 삭제는 AI·permalink 조회 없이 반영하고 당일 DM 갱신 작업을 깨웁니다. 원본 삭제 기록은 이후 도착하는 오래된 생성·수정으로 복구하지 않습니다.
  - 본문이 그대로인 메타데이터 변경은 AI를 재호출하지 않습니다. 신규·수정·삭제와 운영자 재처리의 동시 갱신은 원본 상태와 기존 실패 기록을 검사해 보호합니다.
  - 처리 중 종료된 이벤트는 동일 이벤트 재수신 시 다시 적용할 수 있습니다. 이벤트가 재전달되지 않으면 원문 재수정이 필요하며, 누락 이벤트 자동 조회·작업 큐는 이번 범위에 포함하지 않습니다.
- 합의 범위: `notices/model.py`, 모델 등록과 신규 마이그레이션 추가를 승인받았습니다. 기존 학생·공지·체크리스트 데이터와 Slack 권한·환경변수는 변경하지 않습니다.

## D-025 — 최초 한 번 발송하는 개인 체크리스트와 간결한 목록

- 날짜: 2026-09-17
- 상태: 확정 (사용자 요청, 시작 재입력·해지의 메시지 정리는 D-026으로 대체)
- 내용:
  - D-023의 매일 오전 9시 발송·당일 버튼 제한을 대체합니다. 가입 직후 시간대와 관계없이 개인 DM을 한 번 발송하며, 새 공지·수정·삭제·완료·취소·마감 경과는 최초 메시지에 계속 반영합니다. 재시작·날짜 변경·`시작` 재입력으로 새 메시지를 보내지 않습니다.
  - 기존 `daily_checklist_messages` 스키마와 `DailyChecklist*` 내부 이름은 호환성을 위해 유지합니다. `message_date`는 최초 생성일이며 화면 날짜나 버튼 만료일이 아닙니다. 학생 행 잠금 아래 기존 기록을 찾고 없을 때만 생성합니다.
  - 과거 일일 발송 기록이 여러 개면 주소가 저장된 가장 이른 메시지를 사용합니다. 저장된 주소가 없으면 전송 중/결과 불명확 기록을 우선 확인하고, 나머지는 가장 이른 기록을 재사용합니다. 다른 과거 메시지의 버튼은 차단하며 기록·Slack 메시지는 자동 삭제하지 않습니다.
  - 첫 전송 결과가 불명확하면 날짜가 바뀌어도 자동 재발송하지 않습니다. 기존 메시지가 삭제되어 편집할 수 없는 경우도 자동으로 새 메시지를 보내지 않고 오류를 기록합니다. 해지 시 개인 정보·체크리스트·발송 기록 삭제 정책은 유지하며 재가입은 새 연동으로 봅니다.
  - 화면은 날짜 없는 `내 체크리스트`, 짧은 제목 링크, 마감일·원문 링크, 오른쪽 `✓` 완료 / `↶` 완료 취소 버튼으로 구성합니다. 제목은 화면에서만 공백 정리 후 최대 28자로 줄이며 원래 제목·요약은 DB에 보존합니다. 긴 요약은 목록에 반복하지 않습니다.
  - 후속 화면 요청: 링크 탭처럼 제목과 부가 정보를 구분하기 위해 테두리 컨테이너 안에 굵은 제목과 작은 도메인·마감일·원문을 배치합니다. 큰 달력은 제거하고 목록 전환·새로고침은 카드 아래에 둡니다. 컨테이너가 명시적으로 거절된 경우에만 같은 정보를 일반 블록으로 표시합니다.
  - URL의 호스트·경로에 `form`이 있으면 `📝`, `docs`이면 `📄`를 표시하며 두 조건이 겹치면 폼을 우선합니다. 판별 불가 시 `🔗`를 표시하며 쿼리 문자열로 유형을 판별하지 않습니다.
  - Slack 표 셀에는 조작 버튼을 넣을 수 없으므로 정렬된 짧은 행과 오른쪽 아이콘 버튼을 사용합니다. 단일 목록 전환·새로고침·페이지 이동, 실제 제출 후 완료 처리, 대상·소유권·마감 검증은 유지합니다.
- 변경 범위: 저장소·서비스·화면·문서·테스트를 수정합니다. 사용자 확인에 따라 `slack-manifest.yaml`의 오전 9시 관련 설명도 제거합니다. DB 모델·마이그레이션·권한·환경변수는 변경하지 않습니다.

## D-026 — 시작·해지 시 기존 봇 개인 DM 정리

- 날짜: 2026-09-17
- 상태: 확정 (사용자 요청 및 `im:history` 추가 승인)
- 시작: 성명 검증 후 실행자와 봇의 1:1 DM에서 인증된 봇이 작성한 일반 메시지·답글을 페이지 단위로 모두 조회하고 삭제합니다. 완료 기록은 유지하고 발송 기록만 초기화하여 새 체크리스트 하나를 보냅니다.
- 해지: 같은 정리 후 학생·개인 체크리스트·발송 기록을 삭제합니다. 이미 해지된 학생도 남은 메시지를 정리할 수 있습니다.
- 제외: 학생·다른 봇의 메시지, 공지 채널, 과거 임시 응답. 새 명령 결과는 기존처럼 임시 응답입니다.
- 실패: 일부 삭제 후 실패해도 성공으로 안내하지 않습니다. 기존 발송 기록을 `uncertain`/`dm_cleanup_pending`으로 유지해 재시작 후에도 자동 갱신을 막고, 같은 명령을 다시 실행해 남은 메시지를 정리합니다. 부분 삭제는 복구하지 않습니다.
- 동시성: 단일 프로세스의 공유 잠금으로 명령·버튼·백그라운드 Slack 발송을 직렬화합니다. 여러 봇 프로세스 동시 실행은 지원하지 않습니다.
- 합의 범위: `slack-manifest.yaml`의 `im:history` 추가를 승인받았습니다. 적용 후 앱 재설치가 필요합니다. DB 스키마·환경변수는 변경하지 않습니다.
