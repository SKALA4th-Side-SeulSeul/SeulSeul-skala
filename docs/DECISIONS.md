  - 기능 브랜치와 PR(첫 커밋의 `COLLABORATION.md`): 보류했습니다.

## D-005 — 커밋 메시지 형식

- 날짜: 2026-09-14
- 상태: 확정
- 내용: 커밋 메시지는 `<타입>: <한국어 설명>` 형식으로 쓰고, 한 커밋에는 하나의 목적만 담습니다.

| 타입 | 용도 | 예시 |
| --- | --- | --- |
| `feat` | 기능 추가·변경 | `feat: 체크리스트 배정 서비스 추가` |
| `fix` | 버그 수정 | `fix: 마감일 없는 공지의 알림 누락 수정` |
| `refactor` | 동작 변경 없는 구조 개선 | `refactor: 공지 채널 검증 로직 분리` |
| `test` | 테스트만 추가·수정 | `test: 중복 체크리스트 생성 테스트 추가` |
| `docs` | 문서만 수정 | `docs: 커밋 규칙 정리` |
| `chore` | 설정, 의존성, 스크립트 등 | `chore: Ruff 설정 추가` |

- 이유: 제목만으로 변경 종류를 구분하고, 설명은 팀이 쓰는 언어로 통일하기 위함입니다.
- 포기한 대안:
  - `Add checklist ...`처럼 영어 동사로 시작하는 형식(첫 커밋의 `COLLABORATION.md`): 실제 커밋 방식과 달라 바꿨습니다.
  - `add` 타입: `feat`, `test`, `docs`, `chore`와 경계가 겹쳐 두지 않습니다.

## D-008 — check.sh가 개발 환경을 자동 준비

- 날짜: 2026-09-14
- 상태: 확정
- 내용: `./scripts/check.sh`는 검증 전에 `.venv`를 Python 3.11로 준비합니다. `.venv`가 없거나 버전이 다르면 다시 만들고, pytest·ruff가 없거나 `pyproject.toml`이 바뀌었으면 `pip install -e '.[dev]'`를 다시 실행합니다. Python 3.11 자체는 설치하지 않고 안내만 합니다.
- 이유: 3.11이 아닌 Python으로 만든 `.venv`나 의존성 미설치 때문에 팀원 환경에서 2단계 테스트가 `No module named pytest`로 실패했기 때문입니다.
- 포기한 대안: 실패 시 안내 메시지만 출력. 원인을 사람이 해석하고 명령을 직접 실행해야 해서 채택하지 않았습니다.
- 결과: 에이전트는 모듈 누락 오류를 `.venv` 직접 수정이 아니라 `./scripts/check.sh` 재실행으로 해결합니다.

## D-009 — 공지 수집 채널과 링크 조건

- 날짜: 2026-09-14
- 상태: 확정
- 내용:
  - 다음 3개 채널의 최상위 메시지만 공지 처리 대상으로 삼습니다. 공개 저장소이므로 실제 채널 이름·ID는 문서에 적지 않고 각자의 `.env`(`SLACK_NOTICE_CHANNELS`)에만 둡니다.
    - 기수 전체 공지 채널
    - 캠퍼스 공지 채널
    - 담당 반 공지 채널
  - 스레드 답글은 처리하지 않습니다.
  - 메시지에서 `http://` 또는 `https://` URL을 추출하고, URL의 호스트명이나 경로에 대소문자 구분 없이 `form` 또는 `docs`가 포함된 경우에만 처리합니다.
  - 메시지 본문의 일반 문자열이 아니라 실제 URL을 기준으로 판정합니다.
  - SeulSeul 봇 자신이 작성한 메시지만 제외합니다. 다른 봇이나 앱이 작성한 메시지는 같은 조건으로 검사합니다.
- 이유: Google Forms·Google Docs뿐 아니라 네이버 폼 등 여러 서비스의 제출 링크를 처리하면서, 지정된 공지 채널과 제출 관련 메시지로 범위를 제한하기 위함입니다.
- 결과: Slack 원본 메시지의 수정·삭제 이벤트는 D-012에 따라 기존 체크리스트를 동기화하기 위해 처리합니다.

  - 닉네임 형식이 올바르지 않으면 소속을 임의로 추정하지 않고 자동 배정 대상에서 제외하며 오류를 기록합니다.
  - 채널별 실제 체크리스트 배정 대상은 다음과 같습니다.

| 채널 | 공지의 의미 | 실제 배정 대상 |
| --- | --- | --- |
| 기수 전체 공지 채널 | 4기 전체 공지 | SeulSeul에 등록된 광주캠퍼스 학생 전체 |
| 캠퍼스 공지 채널 | 광주캠퍼스 전체 공지 | SeulSeul에 등록된 광주캠퍼스 학생 전체 |

- 이유: 전체 공지 채널의 원래 대상이 4기 전체이더라도 서비스 범위와의 교집합인 광주캠퍼스 학생에게만 체크리스트를 제공하기 위함입니다.

## D-011 — AI 분석 결과와 실패 처리

- 날짜: 2026-09-14
- 상태: 확정
- 내용:
  - AI는 `title`, `summary`, `deadline_at`, `deadline_source_text`를 포함한 JSON 객체를 반환합니다.
  - `title`은 체크리스트 제목, `summary`는 학생이 해야 할 행동을 포함한 요약, `deadline_at`은 ISO 8601 형식의 마감 시각, `deadline_source_text`는 마감일 판단에 사용한 원문의 표현입니다.
  - 기준 시간대는 `Asia/Seoul`이며, 날짜만 있고 시각이 없으면 해당 날짜의 `23:59`로 처리합니다.
  - 공지에는 마감일이 정확히 하나 존재한다는 제품 전제를 둡니다. 모든 필드는 필수이며, JSON 형식 오류·빈 필드·해석할 수 없는 마감일·여러 마감일은 분석 실패로 처리합니다.
  - `deadline_source_text`가 실제 원문에 존재하는지 검증해 원문에 없는 마감일 생성을 막습니다.
  - 분석에 실패하면 오류 원인을 포함해 최대 3회까지 재시도합니다. 계속 실패한 신규 공지는 체크리스트를 생성하거나 DM을 보내지 않고 `processing_failed` 상태와 실패 원인을 기록합니다.
  - 기존 공지의 수정 내용을 분석하다 실패하면 기존 체크리스트를 유지하고 갱신하지 않습니다.
- 이유: AI의 자유 형식 응답과 잘못된 마감일이 학생의 체크리스트와 알림으로 바로 전달되는 것을 막기 위함입니다.

## D-012 — 공지 식별, 링크 중복과 원본 변경

- 날짜: 2026-09-14
- 상태: 확정
- 내용:
  - Slack 원본 메시지는 `workspace_id + channel_id + message_ts` 조합으로 식별합니다.
  - URL을 정규화한 `canonical_url`을 별도의 링크 중복 판별 키로 사용합니다. 불필요한 쿼리 문자열, fragment와 마지막 `/`의 차이는 제거합니다.
  - 서로 다른 Slack 메시지라도 `canonical_url`이 같으면 이미 처리한 링크로 보고 체크리스트를 추가 생성하지 않습니다.
  - 원본 메시지가 수정되면 D-009의 채널·URL 조건을 다시 검증합니다. AI 분석에 성공하면 기존 공지와 학생별 체크리스트의 제목·요약·마감일을 갱신하되 학생별 완료 상태는 유지합니다.
  - 수정된 원본이 더 이상 처리 조건을 만족하지 않거나 원본 메시지가 삭제되면 연결된 공지와 학생별 체크리스트를 삭제하고 예정된 DM 알림도 취소합니다.
  - 원본 수정 내용의 AI 분석에 실패하면 기존 데이터를 유지합니다.
- 이유: Slack 이벤트의 중복 수신과 같은 링크의 반복 게시로 체크리스트가 중복 생성되는 것을 막고, 원본 공지의 변경을 학생별 체크리스트에 일관되게 반영하기 위함입니다.
