# 제품 개요

## 목표

동일 링크가 여러 반에 게시되면 각 반에 배정하고 학생별로 한 번만 표시합니다(D-027). 현재 학생에게 유효한 반 공지 > 전체 공지 순서로 선택하며 같은 우선순위에서는 최신 게시 원본의 제목·마감일·원문을 보여줍니다. 표시 원본 전환에도 완료 기록을 유지하고, 한 원본이 사라져도 다른 유효한 대상 원본이 있으면 항목을 유지합니다.

Slack에 올라온 공지를 분석해 학생별 체크리스트로 만들고, 필요한 시점에 DM으로 알려줍니다.

## 기본 흐름

```text
Slack 공지
  → 공지 URL·채널 검증
  → 내용 요약과 마감일 추출
  → 학생별 체크리스트 생성
  → 최초 개인 DM 한 번 발송 / 이후 같은 메시지 갱신
  → DM 버튼으로 완료·완료 취소
```

## 용어

| 용어 | 뜻 |
| --- | --- |
| 공지 | 지정된 Slack 채널의 최상위 메시지에서 발견한, `form` 또는 `docs`가 URL의 호스트명이나 경로에 포함된 링크 하나 |
| 채널·URL 검증 | 처리할 채널의 최상위 메시지인지와 실제 URL이 D-009의 조건을 만족하는지 확인하는 단계 |
| 대상 판별 | 공지 채널과 학생 성명에서 판별한 캠퍼스·반을 대조해 공지가 적용되는 학생 범위를 정하는 단계 |
| 학생 | 워크스페이스 사용자 중 Slack 명령어로 알림 수신을 수락한 사람 |
| 소속 | Slack 성명(`profile.real_name`)의 `4기_광주_<반번호>반_<이름>` 형식에서 판별한 학생의 반. 반 번호는 1~4 |
| 알림 설정 | 학생의 알림 수신 수락 여부 |
| 체크리스트 | 공지를 요약한 할 일. 학생마다 완료 여부를 따로 관리합니다 |
| 마감일 | AI가 공지 내용에서 정확히 하나 추출한 `Asia/Seoul` 기준 기한 |

## 초기 처리 범위

- 자동 처리 채널은 봇이 참여한 `.env`의 `SLACK_NOTICE_CHANNELS`에 등록된 채널입니다. 봇을 초대할 수 없는 채널은 `SLACK_MANUAL_NOTICE_CHANNELS`에 등록해 운영자 CLI로만 처리합니다. 모든 채널의 대상은 `SLACK_NOTICE_TARGETS`의 `all` 또는 `1~4`로 명시하며 채널 수나 등록 순서로 대상을 추정하지 않습니다.
- 스레드 답글과 SeulSeul 봇 자신이 작성한 메시지는 처리하지 않습니다.
- 처리 조건을 만족하는 링크 하나를 공지 하나로 봅니다. 한 메시지에 여러 링크가 있으면 링크마다 별도의 체크리스트를 만듭니다.
- 기수 전체 공지 채널과 캠퍼스 공지 채널의 공지는 등록된 광주캠퍼스 학생 전체에게 배정합니다.
- 반 공지 채널의 공지는 해당 채널에 설정된 반(1~4)의 광주캠퍼스 학생에게 배정합니다. 가입·`시작` 재실행 외에도 등록 학생의 `user_change` 이벤트를 받으면 현재 Slack 성명을 조회해 정상적인 반 변경을 자동 반영합니다(D-031). 기존 DM에서 이전 반 항목을 제외하고 새 반·전체 공지를 표시하며 완료 기록은 보존합니다. 새 공지마다 모든 학생의 프로필을 조회하지 않습니다.
- 미가입자·해지자는 성명 변경으로 자동 가입시키지 않습니다. 성명 조회 실패·잘못된 형식은 로그에 남기고 마지막 유효 소속을 유지합니다. 이벤트 누락·실패의 별도 재시도는 없으며 이후 성명 변경 이벤트 또는 `시작` 재실행으로 다시 확인합니다.
- 원본 공지의 수정·삭제는 기존 학생별 체크리스트에도 반영합니다.
- 수정 시 완료 기록은 유지하고 AI 분석 실패 시 마지막 성공 내용을 유지합니다. 제거된 링크·삭제된 원문은 삭제 상태로 기록해 개인 DM에서 제외하며, 같은 원문의 링크 재추가는 분석 성공 후 완료 기록과 함께 복구합니다(D-024).
- 사용자 응답에는 공지 원문 전체를 반복하지 않고 Slack 원문 위치로 이동하는 링크를 제공합니다.
- 사용자는 `/seulseul 시작`으로 가입을 요청한 뒤 성명 검증을 받고, `/seulseul 해지`로 개인 정보와 개인 체크리스트를 삭제합니다.
- 슬래시 명령은 임시 메시지를 보내지 않습니다. 성명 형식이 잘못된 시작 요청에는 수정 방법을 일반 DM으로 보내며 기존 가입·완료 기록을 바꾸지 않습니다. 성명 조회 자체의 실패와 기타 오류는 운영 로그에서 확인합니다. 체크리스트 버튼의 오류 안내는 유지합니다.
- 해지 후에는 일반 DM으로 완료 안내를 보내고 이미 미가입이면 미가입 안내를 보냅니다. 정상 시작 시에는 체크리스트만 전송합니다. 성명 형식 오류의 일반 DM은 위 예외입니다. 안내 전송 실패가 해지된 데이터를 복구하지 않으며 전송 결과가 불명확해도 자동 재전송하지 않습니다.
- 학생용 조회 명령은 제공하지 않습니다. 시작 명령마다 개인 DM의 기존 봇 일반 메시지를 삭제하고 마감 전 미완료 목록 하나를 새로 보냅니다. 완료 기록은 유지합니다. 이후 날짜 변경·봇 재시작에는 같은 메시지를 갱신합니다(D-025, D-026).
- 해지 명령도 기존 봇 일반 DM을 정리한 뒤 개인 데이터를 삭제합니다. 학생 메시지·다른 봇·공지 채널·임시 응답은 정리 대상에서 제외합니다. 정리에 실패하면 명령을 완료하지 않고 자동 갱신을 중지하며 같은 명령 재실행으로 복구합니다.
- `내 체크리스트`와 현재 목록·개수를 제목으로 둔 테두리 카드 묶음 안에 항목을 표시합니다. `📝 폼` 또는 `📄 문서` 아이콘 옆 제목 링크는 굵게, 도메인·`MM/DD HH:MM 마감 · 원문`은 별도의 작은 보조 정보로 표시하며 큰 달력 이모지는 사용하지 않습니다. 제목은 화면에서만 최대 28자로 줄이고 긴 요약은 숨깁니다. DB의 원래 제목·요약은 보존합니다. 오른쪽에는 `✓` 완료·`↶` 완료 취소 버튼을 둡니다. Slack 링크 탭을 복제하는 대신 메시지용 컨테이너를 사용하며 미지원 시 일반 블록으로 동일한 정보를 제공합니다.
- 카드 아래에 반대 목록으로 전환하는 `완료 보기 (N)` 또는 `미완료 보기 (N)` 버튼 하나와 새로고침을 둡니다. 큰 목록 소제목과 두 목록 버튼 상시 표시는 사용하지 않습니다. 날짜가 바뀌거나 새 공지가 도착해도 선택한 목록·완료 상태는 유지합니다. 상단은 `미완료 목록: N개 · 마지막 갱신 MM/DD(목)` 형식이며 완료 목록도 동일합니다. 갱신 날짜·한국어 요일은 서울 기준입니다. 하단 제출 안내·갱신 문구는 제거하고 페이지 표시는 여러 페이지일 때만 나타납니다.
- 최초 연동 시 할 일이 없어도 빈 목록을 한 번 보냅니다. 일반 동기화는 주소가 저장된 최초 메시지를 갱신하며 버튼도 현재 사용 중인 그 메시지에서만 처리합니다. 발송 기록 ID·본인 소유·DM 채널·메시지 ts가 정확히 일치해야 하며, 과거의 다른 메시지·타인·마감·삭제 항목은 차단합니다. 해지 후 재가입은 새 연동으로 처리합니다.
- 일시적 연결·시간 초과·호출 제한·서버 장애는 5분·15분·1시간 간격 최대 3회 자동 재처리합니다(D-030). 내용·설정 오류와 소진된 실패 행은 운영자 CLI로 선택 재처리합니다. 학생 조회·동일 이벤트 재수신은 재분석하지 않습니다. 같은 링크를 새 메시지로 재게시하면 별도 원본으로 분석하며 기존 실패 행 자체를 복구하는 것은 아닙니다(D-027).
- 수동 전용 채널의 공지와 자동 분석 실패 공지는 운영자 CLI에서 Slack permalink·원문 파일로 등록·수정·삭제합니다. AI 실패 시 제목·요약·마감일을 직접 입력할 수 있으며 기존 완료 상태는 유지합니다.
- 운영자 공지 관리는 `./notice.sh`에서 등록·수정·삭제를 선택합니다. 같은 Slack 원문에 링크가 여러 개면 체크리스트 제목의 `[순번/전체]`와 짧은 제출 링크 식별자로 구분하며, 수정은 선택한 링크의 분석값만 바꿉니다. 삭제는 실제 원문 삭제 의미를 보존해 해당 원문의 모든 링크를 삭제 상태로 전환합니다. 원문·완료 기록은 보존하고 AI 실패 시 링크별 수동 입력으로 복구합니다. 기존 `./notice_edit.sh`와 `manual add|edit|delete`도 호환용으로 유지합니다.

## 초기 범위 밖

- Slack 이외의 메신저 지원
- 임의의 모든 메시지에 대한 자동 처리
- 사람이 확인하지 않는 운영 정책 변경

세부 정책은 기능을 구현하기 전에 `docs/DECISIONS.md`에 기록합니다. 공지 수집·대상 판별·AI 분석·중복 처리는 D-009~D-019, 성명 판별은 D-021, 운영자 선택 재처리는 D-022를 따릅니다. D-023의 학생별 배정·개인 DM·완료 상태와 D-024의 원본 동기화를 기반으로, D-025가 발송 주기·메시지 수명·화면 정책을 대체합니다.
