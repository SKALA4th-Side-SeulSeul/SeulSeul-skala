# 관리자 공지 분석 DM 설계

## 목적

공지 링크의 처리 결과를 운영자가 Slack 개인 DM에서 확인하고, 확인한 알림을 `닫기` 버튼으로 삭제한다. 수신자는 `U0BHPU96LG0`, `U0BGTJD4HF0` 두 명이다.

## 범위와 동작

- 공지 원본의 링크마다 저장이 확정된 분석 성공 또는 실패를 두 관리자에게 각각 일반 DM으로 알린다. 신규 공지, 수정, 수동 재처리, 자동 재처리, 운영자 CLI에서 실행한 AI 분석을 포함한다.
- AI 없이 운영자가 직접 입력한 수동 분석은 `AI 성공`으로 표시하지 않는다. 원문 링크 수집 오류는 `수집 실패`로 구별해 알린다. 기존 기록을 그대로 반환한 중복 이벤트, 역순 이벤트, 삭제 이벤트, AI 비활성 상태는 알리지 않는다.
- 성공 DM에는 짧은 제목, 제출 링크, 마감 시각, 원문 링크를 담는다. 실패 DM에는 제출 링크, 원문 링크, 짧고 안전한 실패 사유, 재시도 예정 여부를 담는다. 원문 전체, API 응답, 토큰 형태 값은 싣지 않는다.
- 알림마다 오른쪽 `닫기` 버튼을 둔다. 두 관리자 중 해당 DM의 수신자만 버튼으로 그 메시지를 삭제할 수 있다. 삭제 실패는 임시 응답과 로그로 알린다.
- Slack 발송 실패는 로그에 남기며 공지 저장이나 재처리 결과를 되돌리지 않는다. 자동 발송 재시도나 영속 이력은 추가하지 않는다. 운영 Slack 실송신 확인은 배포 후 별도로 수행한다.

## 접근 방식

1. **분석 시도마다 별도 DM 발송(권장)**: 재시도 결과까지 시간 순서로 남고 DB 변경이 없다. 반복 실패 때 DM 수가 늘어난다.
2. **공지별 DM 하나를 계속 갱신**: 채팅이 조용하다. 재시작 후 같은 메시지를 찾으려면 관리자별 메시지 위치와 상태를 영속 저장해야 해서 D-006의 모델·마이그레이션 합의가 필요하다.

## 구현 경계

`NoticeService`는 저장 확정 후 결과 통지 콜백을 호출한다. `slack/client.py`에서만 Slack API를 호출하고, `slack/views.py`가 Block Kit을 만든다. 버튼 핸들러는 관리자와 실제 DM 채널을 검사한 뒤 `chat.delete`를 호출한다. 관리자 ID는 이 기능의 고정 수신 목록으로 코드에 두며 설정 파일과 DB 구조는 수정하지 않는다.
