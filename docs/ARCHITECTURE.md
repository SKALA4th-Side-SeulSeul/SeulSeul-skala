# 아키텍처 안내

## 패키지 책임

| 위치 | 책임 |
| --- | --- |
| `src/seulseul/slack/` | Slack 이벤트·상호작용 처리, 화면, Slack API 연동 |
| `src/seulseul/notices/` | 공지 메시지 수집, 채널 범위와 URL 검증, 대상 판별 |
| `src/seulseul/ai/` | AI 제공자(NVIDIA Build API 또는 Ollama)를 통한 요약·마감일 추출·검증 |
| `src/seulseul/users/` | 학생, 소속, 권한, 알림 설정 |
| `src/seulseul/checklists/` | 체크리스트 생성·배정·완료 상태 관리 |
| `src/seulseul/jobs/` | 정기 실행과 비동기 작업 |
| `src/seulseul/database.py` | PostgreSQL 연결과 SQLAlchemy 공통 세션 기반 |
| `src/seulseul/config.py` | 환경변수 로딩과 검증 |

## 경계 규칙

- 외부 API 호출은 `slack/client.py`, `ai/client.py`에만 둡니다.
- Slack 명령은 핸들러에서 먼저 `ack()`로 수신을 확인한 뒤 처리합니다. HTTP 요청을 보내는
  Bolt의 `respond` 콜백은 `slack/client.py`의 `SlackCommandResponder`에서만 호출하며,
  슬래시 명령은 빈 `ack()`만 보내고 `respond()`를 호출하지 않습니다. 명령 오류는 민감정보 없이 로그에 남깁니다. 체크리스트 버튼의 오류 응답만 `ephemeral`로 전송합니다.
- 업무 규칙은 도메인별 `service.py`가 담당합니다.
- DB 모델은 도메인별 `model.py`에 두고, 연결은 `database.py`, 도메인별 DB 조작은
  `repository.py`가 관리합니다.
- 영속 엔터티는 학생·공지·체크리스트·개인 DM 발송 기록으로 분리합니다. AI 처리 상태는 공지에, DM 전송 lease·오류·Slack 주소는 호환성을 유지한 `daily_checklist_messages`에 둡니다. `DailyChecklist*` 내부 이름과 `message_date` 생성일 컬럼은 유지하지만 날짜별 발송은 하지 않습니다(D-025).
- `notice_sources`는 Slack 원본별 최신 이벤트 버전·적용 여부·삭제 여부를 보관합니다. `notices/events.py`가 수정의 `message.ts`와 삭제의 `deleted_ts`, 채널·작성자·스레드를 검증하고 공지 서비스가 링크 유지·추가·제거와 실패 시 분석 보존을 결정합니다.
- 공지 저장소는 원본 상태를 잠가 최신 버전을 예약한 뒤 트랜잭션을 종료합니다. AI 호출 후 최신 버전만 반영하고, 공지 갱신과 `checklists/repository.py`의 삭제 상태 변경 함수를 같은 트랜잭션에서 실행합니다. 완료 상태는 변경하지 않습니다. 체크리스트 배정도 공지에 공유 잠금을 걸어 삭제와 경합하지 않게 합니다.
- Slack 핸들러와 뷰는 입력을 검증하고 서비스를 호출한 뒤 응답만 구성합니다. DB를 직접 조작하지 않습니다.
- 운영자 진입점 `notices/retry.py`는 설정·의존성을 구성한 뒤 공지 서비스의 실패 목록·선택 재처리를 호출합니다. DB 갱신은 저장소가 맡고, 실제 AI 호출은 `ai/client.py`를 사용합니다. Slack 연결은 만들지 않습니다.
- 원본 이벤트가 처리 중이거나 삭제된 경우에는 운영자 재처리가 예전 실패 내용을 덮어쓰지 못하게 합니다. 삭제 이벤트는 permalink를 조회하지 않으며, 수정은 저장된 permalink가 있으면 재사용합니다.
- 정기·비동기 작업은 `jobs/tasks.py`에 구현하고 `jobs/scheduler.py`에서 등록합니다. 작업은 서비스를 호출하며 업무 규칙을 다시 구현하지 않습니다.
- 개인 체크리스트 서비스가 채널별 대상을 결정하고 저장소가 학생 행 잠금 아래 배정·개인 상태·최초 DM 전송권을 원자적으로 저장합니다. 최초 연동 즉시 발송하고 이후에는 날짜·시간과 관계없이 같은 메시지를 갱신합니다. Slack 호출은 DB 트랜잭션 밖에서 실행하고 완료 기록은 lease 토큰이 일치할 때만 반영합니다. 내용 hash가 같으면 편집 요청을 생략합니다.
- 과거 발송 기록이 여러 건이면 주소가 저장된 가장 이른 기록을 선택하고, 주소가 없으면 전송 중/불명확 기록을 우선해 중복 발송을 막습니다. 그 외 가장 이른 미발송 기록을 사용하며 아무 기록도 없을 때만 생성합니다. 과거 기록은 삭제하지 않습니다.
- 화면 문구·서식 변경 시 `checklists/service.py`의 `BOARD_PRESENTATION_VERSION`을 올립니다. 이를 hash에 포함해 기존 DM도 한 번 갱신합니다. 갱신 시각만 달라진 경우에는 편집하지 않아 화면의 `마지막 갱신`은 실제로 메시지를 보냈거나 편집한 시각을 유지합니다.
- 체크리스트는 `container` 안에 제목 `section`·보조 정보 `context`를 배치합니다. 5개 항목은 자식 블록 제한 10개에 맞춥니다. Slack이 `invalid_blocks`로 명시적으로 거절한 경우에만 `slack/client.py`가 한 번 일반 블록으로 재구성하고, 같은 클라이언트에서는 호환 레이아웃을 유지합니다. 네트워크 오류·응답 유실처럼 전송 결과가 불명확하면 이 경로로 재발송하지 않습니다.
- 버튼 핸들러는 먼저 `ack()`한 뒤 서비스에 Slack의 워크스페이스·사용자·메시지 주소를 전달합니다. 서비스와 저장소가 가입 여부·소유권·현재 연결된 최초 메시지·유효 항목을 확인합니다. 기본 30초 작업과 변경 신호가 같은 서비스를 사용합니다. 이 작업은 정시 발송 예약이 아니라 신규 공지·마감·복구를 반영하는 동기화 작업입니다.
- 환경변수는 `config.py`에서만 읽습니다. 다른 모듈의 `os.getenv()`, `os.environ` 사용은 Ruff(`TID251`)가 차단합니다.

## 요청 흐름

동일 링크는 `notices`에 워크스페이스·채널·메시지 ts·정규화 URL 조합으로 원본별 저장합니다. `checklists`는 학생·정규화 URL UNIQUE로 한 항목만 보관하고 `notice_id`를 선택된 원본으로 전환합니다. 배정은 학생 잠금과 유효 원본 공유 잠금 아래 수행하며 완료 시각과 체크리스트 ID는 유지합니다. 원본 우선순위는 반 채널 > 전체 채널, 같은 우선순위는 최신 posted_at이며 동률은 채널·메시지 ts·ID로 결정합니다. 조회 대상은 현재 학생 반·워크스페이스 범위와 마감·삭제·분석 검증을 통과해야 합니다. 원본 삭제 시 표시 원본이 삭제 상태가 되어도 다음 동기화에서 다른 유효 원본으로 복구합니다.

해지 완료 안내는 학생 서비스가 삭제 후 주입된 콜백을 호출하고 `slack/client.py`가 `chat.postMessage` 일반 DM으로 보냅니다. 슬래시 명령의 `respond()`는 사용하지 않습니다.

시작·해지의 메시지 정리(D-026)는 학생 서비스의 컨텍스트 콜백으로 체크리스트 서비스를 호출합니다. 단일 프로세스 공유 잠금이 명령 처리와 Slack 발송·버튼 처리를 직렬화합니다. 삭제 전 발송 기록을 `uncertain`/`dm_cleanup_pending`으로 커밋하고, Slack 클라이언트가 본인 DM의 봇 메시지를 모두 정리한 경우에만 발송 기록을 초기화합니다. 삭제 실패 시 같은 명령으로 재시도하며 완료 기록은 시작 시 보존합니다. 과거 메시지 자동 보존 정책은 일반 동기화에만 적용하고 명시적인 시작·해지는 예외입니다.

```text
slack/handlers.py
  → 도메인 service.py
  → repository.py
  → model.py / database.py
  → slack/client.py 또는 ai/client.py
```

실제 구현에서 경계가 달라질 경우 코드를 억지로 맞추지 말고 `docs/DECISIONS.md`에 이유를 남깁니다.
